This adds the tier-b label and the required “Tier-B approval” check: an ordinary PR passes, while a tier-b PR fails until someone other than its author approves the current head; a dismissed, stale or superseded review does not count. The workflow checks labels and new commits immediately and receives submitted, edited and dismissed review events through a signed webhook that dispatches only the PR number to reviewed default-branch code; the five-minute poll remains reconciliation, and no privileged PR code runs. Checks aggregate every open PR sharing a head SHA so an unlabeled sibling cannot override a failing Tier-B decision. The subscription tool previews by default and stays unapplied until Alex says "branch protection on"; its receiver needs TIER_B_REVIEW_WEBHOOK_SECRET and RELEASE_DISPATCH_TOKEN configured after these PRs merge. Single-account catch: until agents push as their own GitHub App identity (#2734), Alex or Fable clicks the Tier-B merge, and the author still cannot approve their own PR. Item 1 makes this check required when Alex explicitly enables protection. Policy tests cover self-approval, independent approval, stale heads and dismissals; nothing merges before “master is current”.
