# #10564 bounded ActivityKit credential retention

PILLARS: TRUTH / FORMATTING

SHIP: Ended or abandoned Live Activities stop retaining usable background credentials, even when an offline phone never returns.

Source-only child of #10542, based on frozen PR10558 `abc4d826b76a0fe371085bd7cec9f97015cbce6c`. No migration was applied, cleanup was scheduled/mounted, configuration was installed, or APNs/device execution occurred.

The first successful server registration stores `created_at` and a nonrenewable `expires_at = created_at + 8 hours`. Rotation and operation replay preserve these fields. Apple documents an eight-hour active Live Activity limit, followed by up to four hours of residual Lock Screen presentation: https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities (verified2026-10-05). This adopted server authorization policy is not device creation time, an observation clock or proof APNs expires the token on that clock. Residual12-hour presentation does not authorize longer credentials. Legacy missing fields fail closed; the source migration adds nullable columns without deriving renewal from mutable `updated_at`.

Registration mutations lock identity before delivery. Expiry is checked before accepting even the latest idempotent PUT. Expired PUT returns409 after durable sanitation. Same-owner GET/DELETE acknowledge inactive state using existing public identity/event/version/is_active fields, with immutable ownership and event validation. Repeated inactive acknowledgment never reactivates or repeatedly increments version. Other-owner requests never borrow credentials or clean someone else's identity. Absent DELETE creates an inactive tombstone with no usable horizon or credential.

Expiry, owner revocation, accepted terminal/stop delivery and the exact APNs `unavailable/token_unregistered` result atomically erase registration token+hash, mark inactive, advance CAS version once (saturating at bigint maximum while inactivity still fences authorization), latch stopped without resetting valid final/ended state or original producer clocks, and clear pending attempt+lease. Corrupt delivery JSON cannot prevent secret erasure: it is replaced by an immutable stopped/no-content state. Codec extraction is shared by worker and lifecycle to avoid a route/worker import cycle; wire shape is unchanged. No registration/tombstone row is TTL-deleted. Tombstones continue protecting the event from merge/prune; account deletion retains the existing explicit registration deletion/delivery cascade.

Observe, reserve and send sample operational time after registration locks. Send rechecks immediately before transport and its timeout is bounded by the remaining fixed horizon and existing25-second ceiling. A request begun before expiry cannot be retroactively retracted. Completion beyond the horizon erases authorization regardless of result. Transient/config errors otherwise retain only the original finite horizon. An expired/unregistered/stopped identity cannot recover through replacement, mutation replay or new retry budgets.

`cleanup_expired` is an explicit unmounted source entry point: default100/hard cap1000 candidates, ordered registration locks with SKIP LOCKED, then delivery locks, no external I/O. It clears due/null-legacy authorization and inconsistent inactive secrets, preserves immutable identity, and is idempotent. Production retention requires an approved caller/schedule and migration application; neither is part of this slice.

The HTTP/native owners agree on uniform expiredPUT409 and same-owner GET/DELETE inactive acknowledgment without new required client fields. Their durable client revoke reconciliation is separate: retain activity/event/owner tuple, retry DELETE only under that same owner even if the ActivityKit object is gone, and preserve local stop until authoritative inactive acknowledgment.

Own gates include horizon creation/rotation/replay, null legacy, owner isolation, expired acknowledgments, original-clock/state preservation, lock-wait operational time, reserved/stale send fences, remaining-horizon timeout, accepted terminal/stop, exact unregistered response, transient/config behavior, bounded/locked/corrupt cleanup and account/merge invariants.
