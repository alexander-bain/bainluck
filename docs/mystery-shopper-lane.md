## Tester feedback intake (both channels)

Adopted 2026-09-22 from Codex's `TESTER-FEEDBACK-TWO-CHANNEL-INTAKE` directive. SHIP: tester reports reach a deliberate issue disposition without Alex forwarding screenshots. This is part of the existing pass, not a new lane, and it is quiet when there is nothing new.

1. **Apple / TestFlight.** Run `python3 ~/bainluck/artifacts/testflight-feedback-intake/read_feedback.py` (read-only, sanitized; no emails or screenshot URLs). Compare the returned record IDs against `cursor.json` in the same directory and inspect only IDs that are not already there. **Every source must report `complete: true`; a raise, an auth failure or an incomplete page is UNKNOWN, never "no feedback".** Read-only Apple access authorizes no upload, distribution, tester invitation or message to a tester.
2. **In-app rage shake.** Check recent issues carrying the `bug-report` label, then reconcile stored reports against them. **Do not call `GET /api/admin/bug-reports` for this: it takes `get_db_rw`, backfills `category` on uncategorized rows and commits, so it is a production write, and it returns `user_email`.** Use read-only `POST /api/admin/db-query` selecting non-identifying columns only (`id, created_at, status, category, backlog_ref, left(description,100)`) — never `user_email` or `screenshot_base64`. Do not submit a test report and do not retry a production task.
3. **Reading the reconciliation.** `backlog_ref IS NULL` alone does not mean undispositioned: rows can be `actioned`/`dismissed` with no ref, and a row with a null ref can still have a filed issue (the Jul 9 auto-filer, #885, wrote refs only from then on). The undispositioned set is `status='new'` AND no ref AND no issue naming the report. Mislinks exist too — see the 2026-09-22 comments on #1563 (pre-#885 residue) and #1774 (reports 143/144 still stored as `#1771`).
4. **Triage each new report.** Preserve build, device, time and surface; distinguish reported from reproduced; check existing issues and whether a newer build already fixed it; attach a recurrence to the true same defect or file one scoped issue. Dedup by hand — keyword auto-priority and the coarse fingerprint (#1774) are not trustworthy. Functional failure and wrong results outrank polish; an idea goes to product review, not automatic bug priority; an unsupported case stays `needs-evidence`. Inspect the existing context before asking Alex or the tester anything. **Never copy a tester identity or email into GitHub.** Do not silently make a report a chart-sprint member or a launch blocker. Close only on outcome evidence or an explicit duplicate / not-a-bug / deferred disposition with its reason; a build-16 report needs carriage into an installable build where that applies.
5. Record the completion cursor after disposition. Stay quiet when healthy or when nothing is new; notify only a meaningful failure needing attention, or an actual reader-facing completion. Confirm the intake ran in the pass receipt.
