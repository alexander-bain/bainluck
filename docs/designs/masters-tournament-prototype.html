Page Composition — How It All Fits Together

Order of sections on the actual /playoffs/golf page when the Masters is live:

Desktop Layout

1. Tournament Header — Masters branding, status, round, sources
2. Odds Movers — Compact pills, biggest swings
3. Bubble Watch — Only during R1-R2, 5 golfers near cut
4. H2H Matchups — Versus cards (if markets exist)
5. Leaderboard + Odds Grid — Main table, full field
6. Hole-by-Hole — Expandable per golfer (tap a row → scorecard)
7. Trend Chart — Top 8 golfers win% over time (already exists)
8. Other Tours — DP World, KFT, LIV grids below

Mobile / iOS Layout

1. Header — Compact, one line
2. Movers — Horizontal scroll pills
3. Bubble Watch — Collapsible, 3 golfers visible
4. H2H — Compact rows (Option B)
5. Leaderboard — Compact rows, tap to expand
6. Hole-by-Hole — Horizontal scroll scorecard

iOS App Note

Same data, native SwiftUI components. The iOS app currently uses the same API — all these features would be available. Native touches: haptic feedback on movers, pull-to-refresh, widget for home screen showing leader + win%.

Design Notes & Open Questions

Green Jacket Theme

The Augusta green (#006747) accent is applied throughout this mockup. On the live site, this would only apply when viewing the Masters — other tournaments keep the default emerald.

Implementation: detect tournament name, swap CSS vars. Pure frontend change.

H2H: Option A vs B?

Option A (versus cards) is more dramatic and engaging — great for 3-5 marquee matchups. Option B (compact rows) is denser — better when there are 10+ matchups.

Recommendation: Option A for desktop (top 3), Option B for mobile (all matchups). This is a persistent solution — the H2H ticker prefix kxpgah2h maps to any golf tournament.

Hole-by-Hole: Data Source

DataGolf's in-play endpoint updates probabilities after each hole, but doesn't give us per-hole scores. We'd compute probability deltas between snapshots. For the actual scores (birdie/bogey), we'd need ESPN play-by-play or StatPal.

DataGolf gives: position, total_score, today_score, thru, round, win/top5/10/20/make_cut probabilities.
ESPN gives: hole-by-hole scores (from competitor detail endpoint).

Bubble Watch Timing

Show the bubble watch section during R1 and R2 only — it disappears after the cut is made. DataGolf's make_cut probability is the signal. Projected cut line estimated from the median of golfers with ~50% make_cut probability.

Post-cut: replace with "Moving Day" section (R3 movers) and "Sunday Contenders" (R4 top 10).
