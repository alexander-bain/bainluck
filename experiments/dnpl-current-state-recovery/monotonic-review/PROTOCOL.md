# Bounded GET lease: request-start monotonic contract (test-only)

The server returns `snapshot.lease_remaining_ms`, a nonnegative integer computed from the original fixed producer-chain expiry at the fresh coherent snapshot for THIS request. It is not the original TTL and is never copied from a cached response. The candidate's allowed lease is at most 60,000 ms. The existing observation timestamp is unchanged. Every live/recovered frame for the same chain carries the same opaque `preview.lease_id`; this rig derives it from event, writer epoch and its existing fixed deadline, not from receipt or attempt time. A production chain identity and atomic storage implementation remain owner work.

Immediately before calling fetch, the client captures `performance.now()` as S. After response parsing, admission uses current monotonic N and deadline D = S + remaining_ms. Admit only while N < D. The response never supplies S. A private WeakMap binds the locally calculated deadline to the parsed frame; JSON cannot manufacture that binding. The one-shot policy independently checks cancellation and its original arm deadline.

Why conservative: with request start at real time t0 and snapshot at t1 >= t0, the server returns R <= E - t1 for its fixed expiry E. D corresponds to t0 + R <= E - (t1 - t0) <= E. Outbound, server-processing, inbound and callback delays therefore consume, rather than renew, the lease. This trades away some valid lifetime for safety; it does not need synchronized client/server wall clocks.

The held preview, render eligibility, expiry timer and persistent chain cap use the same client monotonic domain. Caps survive held=null, expiry, native-open reset and same-chain sequence changes. Subsequent equal-sequence rehydration and live repetitions may not extend an existing cap. Caps are bounded to128 per epoch; overflow refuses a new cap rather than evicting old fences. Epoch advancement safely forgets prior-epoch caps because older epochs remain rejected. Missing chain identity after a GET cap exists is not permission to invent a fresh lease. Revokes and committed revision floors continue to dominate.

This resolves only the GET-recovered chain's unknown CLIENT wall-clock offset/jumps. A never-GET-bound SSE chain retains the earlier bounded-skew experimental policy and is explicitly not fixed here. Server remaining time must itself be coherent, freshly computed and non-increasing for a fixed chain. A server clock rollback that increases remaining duration, stale response caching, a client monotonic clock that pauses in suspension, or clock rate errors outside the duration contract invalidate the proof. These are explicit protocol/environment assumptions, not hidden production guarantees. Hidden/unmount cancellation is preserved; a frozen render thread cannot promise a physical-display expiry instant.

The pending/unavailable UI semantics are unchanged. This is a separate cloud-local protocol prototype, not a production patch, owner takeover, rollout gate, full application build or browser timing claim.
