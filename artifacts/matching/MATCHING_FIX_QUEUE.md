## Incident-meter re-baseline — what “fixed once and for all” means

Once tiers 1–2 (and 3’s precedence table) land, the matching lane **re-baselines** before declaring the next incident noisy:

**What the sentinel page recomputes:**
- `team_identity_mapping` census: `label_only` count and `label_only / total` share per `source` — must not grow for new rows after Tier 1.
- Clock bias: per-namespace `AVG(epoch drift)` for `statpal` vs `espn/odds_api` — `+4.0h/+5.0h` → `<0.5h`.
- ID precedence matrix: `multi` CTE (`external_id`+`espn_id`+`statpal_fixture_id` ≥2) + `commence_time_source` winner + ticker `ABS(epoch diff)` tail — shared `espn_id` collisions → 0 absorbs, ticker never wins time.
- Window distribution: `LEAD(commence_time)` matchup buckets (`<6h / 6–12h / 12–24h / ≥24h`) + ticker drift buckets (`24–28h`) — doubleheader `5–6h` pairs not absorbed, `now`-collapse 177 class → 0.
- No cold-cache `label_only` promotion and no `now`-fallback `commence_time` on unanchored ticker claims (the two pathologies that forced `LIMIT 500` and `ORDER BY time-proximity`).

**What gets published alongside the fix (audit §5 cross-incident synthesis):**
- Per-specimen table (StatPal +4h, shared `espn_id`, 2,069 ticker drifts, Panthers alias drift, 177 collapsed-timestamp) with the § that explains it — so a future incident not in the table is a **new finding**, not a recurrence.
- Per-namespace clock declaration (ESPN/Odds API truth, StatPal corrected, ticker no clock) alongside the window constants they justify.

**Before/after comparison protocol (graded, not declared):**

1. *Snapshot before:* header-only dyno run of all five gate SQLs + greps, save `before.json` (row `COUNT`s / drift histograms / `label_only` tallies / `grep -R register_team_identity` hits). Record the census that gates each queued fix.
2. *Land one tier at a time:* after each tier, re-run `after_tierN.json`. Required movements (from table):
   - After Tier 1 (index): `label_only` new rows → 0, `label_only_fuzzy_created` tail not growing.
   - After Tier 2 (clocks): `statpal` bias `4.0h → 0.0h`, `now`-fallback `commence_time IS NOT NULL` on unanchored ticker claims → 0, collapsed-timestamp `COUNT(DISTINCT commence_time)` no longer 1 for a sport.
   - After Tier 3 (precedence): shared `espn_id HAVING COUNT(*)>1` → 0 absorbs (collisions become duplicates), ticker-vs-event `>6h` drifts all read `authority:event`.
   - After Tier 4 (name matching): `register_team_identity` on fuzzy path grep → 0, `_fuzzy_score 40/60` hits not inserted.
   - After Tier 5 (windows): `LEAD` p1 `<6h` pairs not merged across 6h, `LIMIT 500` no longer needed to hold pathology.
3. *Re-baseline decision:* the next incident after the queue executes must be **EXPLAINED** by one of the five §s or it is a new finding — the queue is proven on four *independent* censuses, not one.
